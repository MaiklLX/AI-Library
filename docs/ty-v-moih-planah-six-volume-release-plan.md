# «Ты в моих планах» — план интеграции шеститомной серии в AI Library

Дата проверки: 31 октября 2026  
Рабочая ветка: `release/ty-v-moih-planah-six-volume`  
Основа: `main` без изменений  
Статус: техническая спецификация; не является публикацией или готовым релизным пакетом.

## 1. Редакционная модель серии

«Ты в моих планах» — один завершённый роман, выпускаемый последовательно в шести томах, а не шесть самостоятельных романов. Сохраняется единая нумерация глав 1–93.

| Том | Подзаголовок | Состав |
|---|---|---|
| I | Тишина между щелчками | Главы 1–16 |
| II | Внутренний маршрут | Главы 17–34 |
| III | До уточнения принадлежности | Главы 35–56 |
| IV | Шестнадцатая строка | Главы 57–66 |
| V | Открыто | Главы 67–80 |
| VI | То, что можно доказать | Главы 81–92 и эпилог 93 |

Общая серия имеет одну страницу-презентацию. Каждый том получает отдельную карточку и отдельную книгу в существующей читалке. Связь между томами задаётся постоянным идентификатором серии и порядковым номером тома.

## 2. Что подтверждено в текущей архитектуре сайта

- Публичный каталог находится в `content/catalog.json`, версия схемы — 1.
- Каталог содержит метаданные, а не тексты глав: `metadataOnly: true`.
- Запись каталога обязана иметь ID, совпадающий с именем JSON-файла: `./content/books/<id>.json`.
- Для закрытой премьеры книга имеет `status: "prerelease"` и пустой массив `chapters`.
- Обычный каталог исключает записи со статусом `prerelease`.
- Страница `premiere.html?book=<id>` загружает одну запись из каталога, затем JSON книги, проверяет статус и показывает презентацию.
- Опубликованная книга получает ID вида `published-<id>`; полное тело загружается только при явном открытии книги.
- Читалка принимает главы как строки или объекты `{title, content}`; при нормализации они преобразуются в отдельные части книги.
- Для опубликованной книги требуется непустой `revision`, совпадающий между каталогом и JSON-файлом.
- Текущий валидатор проверяет уникальность ID, точный путь к JSON, метаданные каталога и отсутствие глав у prerelease-книг.
- Service Worker кэширует оболочку сайта; после изменений интерфейса потребуется согласованное обновление cache version.

## 3. Предлагаемая модель данных серии

Не переиспользовать ID текущей книги для одного из томов. Сохранить `ty-v-moih-planah` как идентификатор главной страницы/премьеры серии, чтобы не ломать уже размещённые ссылки и баннер.

Предлагаемая отдельная запись серии:
- файл: `content/series/ty-v-moih-planah.json`;
- ID: `ty-v-moih-planah`;
- тип: `series`;
- шесть элементов `volumes`, каждый со своим ID книги, номером, названием, подзаголовком, диапазоном глав, статусом, обложкой, аннотацией и путём к JSON книги;
- даты будущих томов не задавать, пока они отдельно не подтверждены.

Предлагаемые ID книг:
1. `ty-v-moih-planah-tom-01`
2. `ty-v-moih-planah-tom-02`
3. `ty-v-moih-planah-tom-03`
4. `ty-v-moih-planah-tom-04`
5. `ty-v-moih-planah-tom-05`
6. `ty-v-moih-planah-tom-06`

Эти ID являются проектным предложением и должны быть закреплены в манифесте до добавления книг в каталог.

## 4. Разделение состояний и доступов

Статус серии и статус каждого тома — разные сущности.

- Страница серии доступна в режиме презентации.
- Каждый том может иметь состояние `planned`, `prerelease` или `published` на уровне манифеста серии.
- Для тома в `prerelease` отдельный JSON книги содержит только метаданные и пустой `chapters`.
- Для тома в `published` JSON содержит полный проверенный текст, `revision` и фактическое количество глав.
- Не публиковать текст будущих томов только потому, что они перечислены на странице серии.
- В карточках будущих томов показывать «Готовится» или «Дата будет объявлена», не рисовать обратный отсчёт без утверждённой даты.
- Дата 2 ноября 2026 года, 18:00 по Москве, сохраняется как целевая дата первого выпуска. Она не является разрешением на автоматическое открытие доступа или на публикацию непроверенного текста.

## 5. Интерфейс серии

Общая страница должна выглядеть как издательская витрина AI Library:
- существующая фирменная тёмная палитра, благородное золото и сдержанный акцентный цвет;
- крупная общая обложка/баннер романа и чёткое обозначение «Один роман · шесть томов»;
- единая аннотация романа, жанр, возрастная маркировка и краткая редакционная заметка;
- горизонтальная/адаптивная последовательность шести томов с номером, названием, диапазоном глав, короткой аннотацией и реальным статусом;
- отдельная кнопка чтения только у опубликованного тома;
- у закрытых выпусков — презентация/статус, но не фиктивная ссылка на читалку;
- на мобильном экране тома располагаются вертикально, без горизонтального переполнения и мелких кликабельных зон.

Не добавлять изображения персонажей. Использовать существующую обложку и баннер, пока не будет отдельного согласованного пакета иллюстраций. Скетчи без лиц можно подключать только после проверки, что читалка корректно отображает их на мобильных устройствах.

## 6. Переходы между томами

- В читалке каждого тома показывать контекст «Том N из 6».
- После последней главы томов I–V предлагать переход на страницу серии и карточку следующего тома.
- Если следующий том закрыт, показывать его статус, но не открывать текст и не обещать дату.
- В томе VI не показывать фиктивный следующий том или рекламу продолжения.
- Прогресс чтения остаётся привязанным к ID конкретной книги; прогресс одного тома не должен перезаписывать другой.
- Не перенумеровывать главы внутри томов: заголовки сохраняют исходные номера 1–93.

## 7. Проверки до любого релизного изменения

1. Сверить каждый JSON книги с манифестом серии и диапазоном глав.
2. Проверить, что в каждом томе нет пропусков, повторов и обрезанных глав.
3. Проверить соответствие каталожного `chapterCount` фактическому числу глав.
4. Проверить уникальность ID томов и путей.
5. Проверить revision между каталогом и телом опубликованной книги.
6. Проверить, что prerelease JSON не содержит художественного текста.
7. Прогнать `node scripts/validate.mjs`.
8. Проверить обычный каталог, страницу серии, прямые ссылки на каждый том и переходы после последней главы.
9. Проверить мобильные ширины, касания, поворот экрана, восстановление прогресса и работу после обновления Service Worker.
10. Проверить фактический запуск GitHub Actions и Pages только на специально согласованном релизном этапе.

## 8. Ограничения текущей задачи

- Не менять `main`, не выполнять merge и не запускать Pages deployment.
- Не менять существующую запись `ty-v-moih-planah` и текущую страницу премьеры до готовности новой страницы серии.
- Не добавлять тексты глав в публичный каталог на этом этапе.
- Не выставлять статус `published` и не открывать чтение.
- Не назначать даты томов II–VI.
- Не готовить PDF/EPUB.
- Не считать расписание публикаций настроенным: в текущем workflow деплой запускается при push в `main` или вручную; отдельного подтверждённого расписания выпуска романа нет.
