## 1. Исправлено взаимодействие серии с читалкой

### Единые идентификаторы томов и книг
Манифест теперь хранит два разных понятия:
- `id` — стабильный ID карточки тома в серии;
- `bookId` — фактический ID книги, который после нормализации в каталоге получает префикс `published-`.

Для тома I сохранён существующий ID премьеры `ty-v-moih-planah`; он совпадает с `premiereBookId`. Томам II–VI назначены проектные bookId `ty-v-moih-planah-tom-02` … `ty-v-moih-planah-tom-06`. Будущие тома не добавлялись в публичный каталог.

### Прогресс чтения
Страница серии теперь ищет прогресс по `published-` + `volume.bookId`, а не по ID карточки. Это устраняет несоответствие для первого тома и задаёт корректную схему для будущих книг.

### Прямые ссылки на чтение
Для тома со статусом `published` карточка формирует ссылку на `index.html?book=published-<bookId>`. Главная страница:
1. загружает каталог опубликованных книг и офлайн-копии;
2. проверяет, что запрошенная книга действительно присутствует;
3. не открывает книгу со статусом `prerelease`;
4. вызывает существующий `openBookById` для доступной книги;
5. очищает query-параметр после обработки.

Текущий том I по-прежнему ведёт на действующую закрытую страницу премьеры; статусы доступа не менялись.

## 17. Сохранение позиции при изменении размера и ориентации экрана (31.10.2026)

Проведён аудит перепагинации читалки при изменении viewport. До исправления обработчик `resize` немедленно запускал `paginateCurrentChapter()` на каждом событии и не учитывал активную анимацию перелистывания. При серии resize-событий это создавало лишние повторные измерения, а при повороте устройства во время перелистывания — риск пересчитать страницы до того, как анимация зафиксирует новый индекс.

Исправление в `index.html`:
- resize и orientationchange используют общий отложенный обработчик с debounce 120 мс;
- перед перепагинацией вычисляется текстовое смещение текущей страницы, затем новая пагинация восстанавливает ближайшую страницу к этому смещению;
- если событие пришло во время page-turn animation, перепагинация откладывается до завершения callback анимации;
- все три пути завершения анимации (обычный spread/single-page, paper-sheet и fallback без host) вызывают flush отложенного resize;
- если читалка закрылась до срабатывания таймера, ожидающее состояние сбрасывается.

Это сохраняет текстовую позицию при переходе между одиночной страницей и разворотом, не пытаясь пересчитать DOM в середине анимации. Перепагинация не изменяет текст главы и не затрагивает сквозную нумерацию книги: номера страниц по-прежнему вычисляются общей метрикой книги после нового layout.

В `scripts/validate.mjs` добавлены статические проверки:
- debounce и задержка 120 мс;
- сохранение текущего текстового offset;
- отложенная обработка при `readerTurnInProgress`;
- общий обработчик для resize и orientationchange;
- вызов flush во всех трёх путях завершения анимации.

## 19. Офлайн-fallback при HTTP-ошибках сервера (31.10.2026)

Проверен Service Worker и путь получения каталога/манифестов/текстов. Выявлен крайний сценарий: network-first ветки возвращали ответ сервера напрямую, если запрос завершался HTTP-ответом с ошибочным статусом (например, 500 или 503). Cache fallback срабатывал только при исключении fetch/сетевом отказе. Поэтому при временной ошибке сервера уже сохранённая офлайн-страница или копия JSON могла не использоваться.

Исправление в `sw.js`:
- для навигации успешный ответ сохраняется в cache и возвращается; при неуспешном HTTP-ответе сначала проверяется сохранённая версия запрошенной страницы, затем app root и `index.html`; если ничего нет, возвращается исходный ответ сервера;
- для `content/catalog.json`, `content/books/` и `content/series/` успешный same-origin ответ сохраняется и возвращается; при неуспешном HTTP-ответе используется сохранённая версия конкретного ресурса, если она есть, иначе сохраняется исходный ответ;
- сетевые исключения по-прежнему обрабатываются прежним offline fallback;
- cache version увеличена с v60 до v61, чтобы браузеры активировали обновлённый Service Worker и новый app-shell cache.

В `scripts/validate.mjs` обновлены ожидания cache v61 и добавлены проверки fallback для non-2xx HTTP-ответов как у навигации, так и у каталогов/манифестов/книжных JSON.
