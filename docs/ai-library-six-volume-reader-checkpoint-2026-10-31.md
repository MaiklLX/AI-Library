## 1. Исправлено взаимодействие серии с читалкой

### Единые идентификаторы томов и книг
Манифест теперь хранит два разных понятия:
- `id` — стабильный ID карточки тома в серии;
- `bookId` — фактический ID книги, который после нормализации в каталоге получает префикс `published-`.

Для тома I сохранён существующий ID премьеры `ty-v-moih-planah`; он совпадает с `premiereBookId`. Томам II–VI назначены проектные bookId `ty-v-moih-planah-tom-02` … `ty-v-moih-planah-tom-06`. Будущие тома не добавлялись в публичный каталог.

### Прогресс чтения
Страница серии теперь ищет прогресс по `published-` + `volume.bookId`, а не по ID карточки. Это устраняет несоответствие для первого тома и задаёт корректную схему для будущих книг.

### Прямые ссылки на чтение
Для тома со статусом `published` карточка формирует ссылку на `index.html?book=published-<bookId>`. Главная страница:
1. загружает каталог опубликованных книг и офлайн-копии;
2. проверяет, что запрошенная книга действительно присутствует;
3. не открывает книгу со статусом `prerelease`;
4. вызывает существующий `openBookById` для доступной книги;
5. очищает query-параметр после обработки.

Текущий том I по-прежнему ведёт на действующую закрытую страницу премьеры; статусы доступа не менялись.

- для общей книги возвращает true и при успешной сетевой загрузке, и при успешном открытии ранее сохранённой офлайн-копии;
- обработчик ?book= очищает адресную строку только если функция вернула true.

В scripts/validate.mjs добавлены проверки контракта результата и условного удаления query-параметра. Первый запуск новой проверки завершился ошибкой из-за двойного экранирования скобок в регулярном выражении теста; выражение исправлено. Ошибка не относилась к коду читалки. После исправления проверены восемь inline-скриптов и Service Worker на синтаксис; отдельно в изолированном JS-прогоне проверены сценарии: неизвестная книга — false, prerelease — false, ошибка загрузки — false, успешная загрузка — true, пустая книга — false.
